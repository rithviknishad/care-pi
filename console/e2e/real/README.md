# e2e/real: journeys against a real device

The specs in this directory run against a real care-pi device, not against the mock.
`playwright.config.ts` (the default `npm run test:e2e`) ignores this directory.
Run them with `playwright.real.config.ts`:

```sh
npm run test:e2e:real -- e2e/real/desktop.setup.spec.ts --project=desktop
```

| Spec                     | Project                          | Device state before                                                   | What it does                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------ | -------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `desktop.setup.spec.ts`  | `desktop` (Chromium, 1280 × 800) | Setup mode, not claimed (`install.sh` without `--unattended`)         | Claim with the claim code, recovery codes (download the `.txt`), each wizard step on the easy path (and the env step on the advanced path), finish, the setup job over SSE (the step list must only append), the hand-off card, the dashboard. Writes `STATE_DIR/desktop.json`.                                                                                                                                          |
| `phone.setup.spec.ts`    | `phone` (WebKit, iPhone 13)      | Setup mode, not claimed                                               | The same journey on a phone (`setup-journey.ts`). Writes `STATE_DIR/phone.json`.                                                                                                                                                                                                                                                                                                                                         |
| `phone.ready.spec.ts`    | `phone` (WebKit, iPhone 13)      | Ready                                                                 | Login, dashboard (8 cards, the units as cards, no horizontal scroll of the page or the units card, no cut label or value, no move across 2 refreshes), certificate (fingerprint, Apple profile, QR code), logs (follow), TOTP on, logout, login with TOTP, TOTP off. Writes `STATE_DIR/phone.json`.                                                                                                                      |
| `desktop.resume.spec.ts` | `desktop`                        | Ready                                                                 | Opens the dashboard with `desktop.json`, without a login (for example after a reboot).                                                                                                                                                                                                                                                                                                                                   |
| `desktop.job404.spec.ts` | `desktop`                        | Ready                                                                 | The progress page of a job that does not exist: `404 job-not-found`, the reads stop.                                                                                                                                                                                                                                                                                                                                     |
| `phone.revoked.spec.ts`  | `phone`                          | Ready, the phone session revoked (`care-pi auth sessions revoke REF`) | `GET /session` gives `401`, the console opens the login page.                                                                                                                                                                                                                                                                                                                                                            |
| `backups.spec.ts`        | `desktop` and `phone`            | Ready (Phase 3)                                                       | The Backups page (health row, local backups, key, destinations; the card boxes do not move across a reload with held requests; no side scroll), the dashboard row, the restore window. With `BACKUP_JOBS=1` (desktop): Back up now, Verify, and the test restore. With `BACKUP_ADD_DEST=1`: add `BACKUP_DEST` from the Backups page. With `BACKUP_PITR=1`: a restore to 2 minutes ago and its undo (Care stops 2 times). |

The setup journeys claim the device. Each works one time for each install. `setup-journey.ts` has their steps.
The step backups uses `BACKUP_DEST` (`backups-journey.ts`): the journey makes the recovery key, writes its words to
`STATE_DIR/recovery-key.txt` and the `.txt` file of the agent to `STATE_DIR`, confirms 3 words, and adds the destination.
Without `BACKUP_DEST`, the journey skips the step (only a dev build allows it).

## Variables

| Variable                                                                                                                                                        | Use                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BASE_URL`                                                                                                                                                      | The console, for example `https://care.local:8443`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `CLAIM_CODE`                                                                                                                                                    | The claim code that the installer printed (`sudo care-pi auth claim-code`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `CONSOLE_PASSWORD`                                                                                                                                              | The console password that the claim sets (and the login uses).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `CARE_USERNAME`, `CARE_EMAIL`, `CARE_PASSWORD`                                                                                                                  | The Care administrator of the setup. The password must not be the console password.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `DISPLAY_NAME`                                                                                                                                                  | The clinic name of the identity step.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `CA_CERT`                                                                                                                                                       | The root CA of the device (PEM): `/var/lib/care-pi/caddy/caddy/pki/authorities/local/root.crt`. The specs verify the served chain against it, compare the fingerprint, and compare the DER in the Apple profile.                                                                                                                                                                                                                                                                                                                                                                                    |
| `NODE_EXTRA_CA_CERTS`                                                                                                                                           | Set it to `CA_CERT`. The API requests of the tests (`page.request`) then trust the device.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `CHROMIUM_SPKI`                                                                                                                                                 | Optional. Chromium has no option to trust one CA. It accepts the certificates with these SPKI hashes (base64 SHA-256). Give the hash of the intermediate that the device serves, after `openssl verify -CAfile "$CA_CERT"` passes on it. Without it, Chromium ignores the certificate errors. WebKit always ignores them (Playwright has no other option for WebKit).                                                                                                                                                                                                                               |
| `PROXY`                                                                                                                                                         | Optional. An HTTP proxy for the browsers and for the chain check, for example when the device is on another network behind an ssh tunnel.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `EXPECT_HOSTNAME`, `EXPECT_IPS` (comma-separated), `EXPECT_RAM` (`2 GiB`), `EXPECT_PAGE_KIB` (`16`), `EXPECT_DISK_KIND` (`USB drive`), `EXPECT_RTC` (`Present`) | Optional. The values that the hardware and identity steps must show. Empty: not checked.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `SHOTS_DIR`                                                                                                                                                     | The screenshots (`<project>-<step>.png`), the journey log, and the step timeline of the setup job.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `STATE_DIR`                                                                                                                                                     | The storage states (`desktop.json`, `phone.json`) and the downloaded recovery codes. Keep it private: the files hold session cookies and recovery codes.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `OUTPUT_DIR`                                                                                                                                                    | The Playwright output (traces and screenshots of failed tests).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `BACKUP_DEST`                                                                                                                                                   | The destination of the step backups and of `BACKUP_ADD_DEST`: `folder` (`BACKUP_FOLDER`), `usb` (`BACKUP_DISK`: a text of the disk row, for example the model; a disk without care-pi backups is erased only with `BACKUP_DISK_WIPE=1`), `sftp` (`BACKUP_SFTP_HOST`, `BACKUP_SFTP_PORT`, `BACKUP_SFTP_USER`, `BACKUP_SFTP_PATH`; `BACKUP_SFTP_FINGERPRINT` is the expected `SHA256:` fingerprint of the server), or `s3` (`BACKUP_S3_ENDPOINT`, `BACKUP_S3_REGION`, `BACKUP_S3_BUCKET`, `BACKUP_S3_PREFIX`, `BACKUP_S3_ACCESS_KEY`, `BACKUP_S3_SECRET_KEY`). `BACKUP_NAME` sets the destination id. |
| `BACKUP_SFTP_WAIT_S`                                                                                                                                            | SFTP: the journey writes the line for `authorized_keys` to `STATE_DIR/sftp-authorized-key.txt` and tests again each 10 s for this time (default 180). Add the line on the server in that time (for example with `ssh`). The key comes from the new recovery key, so it is new for each setup.                                                                                                                                                                                                                                                                                                       |
| `BACKUP_JOBS`, `BACKUP_ADD_DEST`, `BACKUP_PITR`                                                                                                                 | `1` turns on the journeys of `backups.spec.ts` that change the device.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `SETUP_TIMEOUT_MIN`                                                                                                                                             | The time limit of the setup job (default 12 minutes).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

Each spec also checks that each request of the page stays on the origin (`e2e/fixtures.ts`).
